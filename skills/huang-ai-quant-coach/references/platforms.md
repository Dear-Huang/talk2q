# 平台路由与共同验收

先识别产品、入口和版本，再读对应适配；已有环境信息直接复用：

- [聚宽](joinquant.md)：网页云端策略；JQData本地取数另算。
- [BigQuant](bigquant.md)：`bigtrader.run`与模块化入口不能混用。
- [米筐](ricequant.md)：云端、Plus、开源、RQData分开。
- [掘金](myquant.md)：先取当前官方模板，尚无本包完整API核验。
- 其他平台：查该平台官方资料，不以相似函数名迁移。

## 提交代码前

逐项核对：导入/版本、回调签名、证券编码、数据结构、时间口径、财务公告日、费用单位、仓位单位、未成交、结果/日志。卡与代码双向映射；接口未证实就列为待核实，不输出一段假装最终可运行的代码。

如环境可运行Python，可用`scripts/check_strategy.py`对策略作离线语法与有限混用检查（参见脚本帮助）。该脚本不执行策略、不能查数据权限/官方接口存在性，也不能证明无前视、收益正确或能在平台运行。

真实执行应覆盖买入与卖出两个分支，以及首日预热、低资金/最低佣金、已有仓位不重复补仓。按策略实际需要补未成交/部分成交等边界。不要把多个层级合成一个“通过率”；分别记录静态、签名、回调桩、真实引擎合成数据、真实平台历史行情。对账现金要使用相同事件/结算时点。

## 分层排错，不靠整段重写

| 现象 | 先看什么 | 不可用的“修法” |
|---|---|---|
| ImportError/找不到模块 | 平台入口、Python/包版本、云端专用模块 | 在本机乱装同名包，或删财务模块 |
| AttributeError | 所属对象、当前签名、旧/新模板差异 | 不查文档给对象猜属性 |
| TypeError/缺少参数 | 注册回调与函数参数、关键字版本 | 无脑添加`*args`隐藏问题 |
| 表/字段不存在或空表 | 数据字典、权限、日期、证券编码、类型 | 自动改字段、用最新数据补过去 |
| pandas/数组索引错误 | shape、columns、index、长/宽表 | 转置/填0直到不报错而不核口径 |
| 无订单或无成交 | 定时是否触发、信号、整手/T+1/涨跌停、现金、订单状态 | 把日志“已下单”当成交 |
| 收益异常好 | 同日可得数据、双重移位、费用、未卖持仓 | 只调参数让曲线“合理” |
| 模拟没跑 | 权限、绑定代码、交易日、回调时间、真实日志 | 根据“运行中”口头确认交易成功 |

每次只修有证据的错误，列变更与R编号，规则不变；需改规则则先确认。保留原错误/原代码/修订版，再做同一路径验证。只有真实平台跑完才升级状态。
